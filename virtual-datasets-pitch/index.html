Define a group of datasets once, with DataPrime. Give it a name. Every query, dashboard and alert uses that name, and stays right when your datasets change.

The problem today

Nine datasets. Every query lists all nine.

A transportation company split its platform data into nine datasets, one per service. It was the right call for cost and access. Then every investigation started like this:

source platform-api-logs, platform-auth-logs, platform-billing-logs, platform-dispatch-logs, platform-gateway-logs, platform-matching-logs, platform-notify-logs, platform-payments-logs, platform-routing-logs
every day

Nine names in every query.

Each engineer types or copies the same list. Each dashboard and alert carries its own copy.

when data moves

A tenth dataset breaks the list.

Someone must find and edit every query, dashboard and alert by hand.

the real cost

A missed copy fails in silence.

The query still runs. It just leaves data out. An alert that should fire stays quiet, and nobody knows why.

The idea

A virtual dataset is a saved DataPrime query that reads like a dataset.

You write the definition once: which datasets to read, and which data to keep. After that, it is just a name.

1 · define it once
# platform_data source platform-api-logs, platform-auth-logs, … platform-routing-logs | filter $d.env == 'production'

Pick the sources. Add a DataPrime filter to keep only the data that matters, for example production only.

2 · use the name everywhere
source platform_data | filter $m.severity == ERROR

Explore, dashboards and alerts read it like any dataset. Add your own DataPrime on top, as you do today.

Physical and virtual, together

Store data the way it costs least. Query it the way people think.

Physical datasets decide where data lives: its retention, its quota and who can read it. Virtual datasets decide how people find it. You split data for cost and control, and your team still sees one name.

What changes for you

Change your data layout. Not your queries.

One change, every query.

Add or remove a dataset in the definition. Every query, dashboard and alert that uses the name follows at once.

One definition of the data.

The sources and the filter live in one place. Every team reads the same data, not their own copy of the list.

Access stays as it is.

A virtual dataset does not copy data. The access rules of each dataset it reads still apply.
