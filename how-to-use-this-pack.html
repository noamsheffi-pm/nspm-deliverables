The idea

A vault is a schema, not a pile of notes

Notes you write freely are only useful to you. Notes that follow one shape are useful to tools. This pack gives you that shape. You get live portfolio views on day one. Later, the same shape is what lets Claude agents read your work without guessing.

Why the structure comes first

Part 2 of this setup adds Claude Code: slash commands, vault search, scheduled agents. Those only work if the structure is already there. Build the vault now, add the automation after.

Install

Four steps
  1. 1

    Set your product areas

    Open install.sh and edit the PORTFOLIO list near the top. One entry per area you own. It ships with Tracing and Explore.

    # --- EDIT ME ---
PORTFOLIO=(
  "Tracing"
  "Explore"
)
  2. 2

    Run the script

    Pick any local folder. Avoid iCloud Drive, it causes sync conflicts on large vaults.

    bash install.sh ~/Vault

    Safe to run again. It never overwrites a file that already exists.

  3. 3

    Open the vault in Obsidian

    Install Obsidian from obsidian.md, choose Open folder as vault, pick the folder you just built.

  4. 4

    Install four plugins

    Settings, then Community plugins, then Browse. Install and enable these:

PluginWhat it does for you
DataviewBuilds live tables from your frontmatter. This is what makes the dashboard work.
TemplaterTurns the four templates into one keystroke.
TasksFinds every open #Task across the whole vault.
OmnisearchFast full text search. Better than the built in one.

Do not add more plugins in week 1

The setup guide lists six more as recommended and a longer list to skip. Add one only when you feel the problem it solves. More plugins early makes the setup harder to trust.

Structure

Three levels, top to bottom
Level 1

Product folders

Top level folders map one to one to the areas you own. Same names you use at work. Plus the cross cutting folders the script creates: Meetings, Daily Notes, Roadmap, Customers, Dashboards, System, Archive.

Anything looking for your work knows which folder it belongs to before reading a word.

Level 2

Initiative folder

Every initiative is a folder, not a file, and every one has the same shape.

Tracing/Trace Sampling Controls/
├── 00-workplan.md      # source of truth
├── prd-*.md            # the PRD
├── spec-review-*.md    # architecture review
├── Meetings/           # meetings on this work
└── 04-dev/             # epics, breakdown

Every artifact links back to the workplan. The folder is the context you hand over later.

Level 3

Frontmatter

The YAML block at the top of 00-workplan.md. This is the spine. It is what the dashboard reads today and what agents read later.

---
type: workplan
area: Tracing
phase: discovery | definition | dev | release | done
status: active | paused | done
blocker: ""
next-action: "Get sizing from the team lead"
owner: Lior
last-reviewed: 2026-08-29
---
FieldThe question it answers
phaseWhat stage the work is in. Gate everything on this.
next-actionWhat is owed right now, and by whom.
blockerEmpty means not blocked. Anything else means blocked.
last-reviewedFreshness. If it is old, the note is lying to you.

One YAML rule that breaks people

If a value contains a colon followed by a space, put it in quotes. Without quotes the block breaks and Obsidian stops showing Properties. This is the most common reason a row does not appear on the dashboard.

Daily use

Tags go at the end of the line

Tools read tags by position, so put them last. Four tags cover almost everything.

TagMeaningExample line
#TaskYou need to do thisAsk the team lead for sizing #Task
#follow-upWaiting on someone elseWaiting on the customer to confirm volume #follow-up
#decisionA decision was madeSpans stay out of v1 scope #decision
#open-questionStill unresolvedIs sampling per service or per tenant #open-question

The one habit that makes all of it work

When you finish working on an initiative, update two fields in its workplan: next-action and last-reviewed.

That is the whole discipline. The dashboard, the stale view, and everything in part 2 run off those two fields. Skip them and the vault becomes a pile of notes again.

Dashboard

What you get on day one

The script writes Dashboards/portfolio.md. It is empty until you have workplans, which is correct. Four live views, no work to maintain them.

Needs a next action
Every open initiative with its phase and what is owed.
Stale
Anything not reviewed in 14 days. Your weekly cleanup list.
Blocked
Everything with a blocker set, and who owns it.
Open tasks
Every unfinished task in the vault, sorted by due date.

Test that it works

Copy System/Templates/00-workplan.md into a real initiative folder, fill area, phase and next-action, then open the dashboard. The row should appear. If it does not, check the YAML quoting rule above.
