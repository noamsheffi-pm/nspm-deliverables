Pipeline · TCO

Cost Control Reaches Spans

Graceful Span Cost Control

Span quotas no longer flip straight to block. As a span quota fills, ingestion priority steps down through multiple thresholds, so the least valuable traces degrade first and the important ones keep their priority. Metering, ingestion-priority transition and the policy editor all landed together.

↗ Roadmap card

Multi-Threshold Stepping

Priority steps down gradually as the quota fills, instead of a single cutoff to block.

Span Policy Editor

Author and manage span TCO policies with default-dataset and multi-quota support.

Metered by Applied Priority

Usage is recorded against the priority actually applied, so cost matches what was ingested.

Same Controls as Logs

Span cost control uses the TCO policies and quota model you already know.

TCO Spans: Priority Block on Ingest Rolling Out

The bottom of the priority ladder is now a real stop. A Block priority on spans drops the lowest-value traces at ingest rather than storing and charging for them, with the blocked state visible in the policy UI and the trace view.

Block at Ingest

Spans matching a Block priority are dropped before storage, not filtered after the fact.

Visible in the Policy UI

Block appears as a first-class priority in the span policy editor.

Trace View Reflects It

The trace view shows when data is absent because a Block priority applied.

Completes the Ladder

High, medium, low and now block. The full range of span priority is configurable.

Monetization · Quota

Quota Becomes Movable

Unit-Based Quota Rules

Quota is expressed in units rather than raw volume, so one currency covers every entity type and a reservation means the same thing wherever you read it.

↗ Roadmap card

Units as the Model

One unit currency across entity types, instead of per-pillar volume rules.

Reservations Enforce

A reserved allocation is applied in the entity-type blocker, not a soft target.

One Currency

Quota Rules and Org Quota Manager express allocations in the same units.

CX-bot Operations

Quota and data-usage operations available through CX-bot commands.

Move Units Between Teams Rolling Out

Org admins can rebalance quota across teams without re-contracting. A guided drawer moves units from a source team to a target with a live preview before you commit, and locked allocations are protected from being moved out from under the team that depends on them.

↗ Roadmap card

Guided Move Drawer

Source row, target card, amount and a live preview of the result before you apply.

Locked-Unit Guard

The flow excludes locked allocations from the movable pool and shows how much is protected.

Replaces the Legacy Modal

One drawer for the whole flow, with the table updating in place on apply.

No Re-Contracting

Capacity moves where it is needed without a commercial change.

Monetization · Usage & AI

Usage Gets an Owner

Unified Usage Analytics

Consumption across every team in the org, in one place. Pick the teams you are entitled to see, query them together, and get one answer to “which team spent what, on which data” instead of a per-team hunt.

↗ Roadmap card

Multi-Team Query

Query consumption across teams from one entry point rather than switching contexts.

Eligible-Team Selection

A checkbox column and count make it explicit which teams you can include.

Org-Level DataPrime

Cross-team usage is queryable in DataPrime, so there is no separate reporting path to learn.

Answers Chargeback

Attribute spend to the team that caused it without exporting and reconciling by hand.

Olly on the Quota Surfaces Rolling Out

Olly is now embedded in the screens where you manage consumption: Quota Rules, Org Quota Manager and Data Usage. Ask in natural language on the surface you are already using, instead of leaving to assemble a query.

Olly in Quota Rules

Ask about rules, reservations and usage against them without leaving the screen.

Olly in Org Quota Manager

Query org-level allocation and movement in natural language.

Olly in Data Usage

Interrogate consumption directly on the usage surface.

No New Destination

The assistant comes to the screens you already use.

Team API Keys in Data Usage Rolling Out

Usage can now be attributed to the caller that generated it. The Olly tab shows identity type and name per caller, so AI consumption stops being one anonymous total and becomes traceable to a team API key.

Caller Attribution

Identity type and name per caller on the Olly usage tab.

Detailed CSV Export

Caller-level detail carried through to the Olly detailed-report export.

Legend Differentiation

Callers are visually distinguishable in the usage breakdown.

Who Spent the AI Budget

Turns an aggregate AI number into an accountable one.

Governance · Schema

Know and Guard Your Data

Schema Explorer Reports

Two gaps closed in Schema Explorer. Keypaths nested under array fields are now findable in tree mode, where before they were invisible to search. And frequent-search reporting is split out for logs, so the top-searched fields are not diluted by other data types.

Nested Keypath Search

Tree mode surfaces keypaths nested under array fields, which were previously unfindable.

Frequent Search, Logs Split

Frequent-search reporting separated for logs, backed end-to-end in schema-store.

Search Reaches the Whole Tree

Nested paths are returned, not only top-level fields.

Backed End-to-End

Content-Structure backend and Phoenix frontend shipped together.

Reserved Fields for Every Dataset Rolling Out

Reserved field types are now managed per dataset instead of one global setting, so default/logs and a custom dataset can each carry the types that suit them. The candidate list shows the fields actually observed in the data, so the choice is grounded in what is really arriving.

↗ Roadmap card

Per-Dataset Configuration

Reserved field types set independently for each dataset, not one global rule.

Observed Fields Shown

Candidate lookup shows the fields actually seen in the data, so choices are grounded.

Dataset-Scoped API

A dataset-scoped namedSchema get/set reads and writes reserved fields per dataset.

Shared Selector

The dataspace and dataset selector is now a shared component across governance screens.

Dataset Guardrails

Two guardrails that stop bad dataset configuration before it costs anything: bucket and name validation in the Create Dataset drawer, and quota limits on datasets in the default/ dataspace.

↗ Roadmap card

Bucket Validation

The Create Dataset drawer validates the bucket and the fully-qualified name up front.

default/ Quota Limits

Datasets in the reserved default/ dataspace can carry quota limits like any other.

Fail at Creation

Misconfiguration surfaces in the drawer rather than as missing data later.

Reserved Dataspaces Covered

Governance applies to the dataspaces customers do not create themselves.
