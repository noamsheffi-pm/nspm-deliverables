One place to decide where data goes, who sees it, and how long it is kept

Datasets give an IBM Cloud Logs instance named collections of data. Each one has its own storage, retention and access, set once by the admin.

Layer 2

Dataspace

A group of datasets that belong together, for example one team or one product area.

The tier name, such as Priority insights, is part of how a query reads it.

Layer 2

Dataset

A named collection of data inside a dataspace, for example payments-logs or checkout-logs.

It holds the settings for that data: where it is kept, how long, and who can see it.

What it gives an IBM customer

Access per dataset

Data access rules apply to a dataset, so a team sees its own data and not the whole instance.

Storage and retention per dataset

Each dataset points at its own COS bucket and retention. Payment logs can be kept longer than debug logs.

Streams as a target

A dataset can send its data to an Event Streams topic instead of storing it, as part of the same setup.

Clear usage per dataset

Data usage shows one row per dataset, streams included, so the customer sees what each team sends and where it goes.

Simple routing

The TCO policy names the dataset. It does not need to know which bucket or topic sits behind it.

Same model, UI and API

Everything set on the screens can also be set through a public API, so customers can automate it.

05

Open topics: we want your view

Question 1COS bucket

Should buckets stay in resource control, or be managed with the datasets?

Today the bucket is set in IBM resource control and shown read-only. With datasets, a customer may want more than one bucket and to pick one per dataset.

Question 2Streams: tier and charging

How should streamed data be charged, and on which tier?

A stream dataset goes through TCO, so it has a tier. On Analyze and alert, real-time alerts run. On Store and search, cost is lowest. We report stream volume per dataset and tier.

Question 3APIs

Which of your flows use today's scope and stream APIs?

New: a public API for dataspaces and datasets (create, update, delete, list, get) and one for physical locations. Changed: stream setup moves onto datasets.
