Reserved column: two options

Mock of the Schema Explorer table. Example fields, not real data. Use the switch to compare a frequent search dataset with an archive dataset. New parts are shaded yellow.

ReservedThe user put the field on the reserved list. This is the cause.
MappedThe field is in the OpenSearch index. Frequent search datasets only. This is today's Mapping Status column.
MaterializedThe field has its own column in the archive Parquet files, so queries read it fast. Archive datasets. Nothing shows this today.
Option A

Keep Mapping Status, add a new Reserved column

  • Two columns describe speed: one for the index, one for the archive.
  • On frequent search the user sees Mapping and Reserved side by side.
  • On archive, Mapping is hidden (CX-70168), so only the new column shows.
Option B

One "Fast to query" column plus a Reserved badge

  • Mapping Status is renamed and works on every dataset: Mapped on frequent search, Materialized on archive.
  • Reserved is a small badge on the field name, not a column. A "Reserved only" chip above the table filters to reserved fields.
  • One place to answer "is this field fast?". Needs Phoenix to change an existing column.

"Not known": we have not collected archive data for this field yet, so we cannot say. It must never show as "Not materialized". The time in the column header is when the archive was last checked.
